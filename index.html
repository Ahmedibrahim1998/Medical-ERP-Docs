Introduction

Medical ERP runs a clinic, polyclinic or small hospital end to end — reception, the clinical record, billing, pharmacy, laboratory, insurance and payroll — in one multi-branch system that works in Arabic and English.

It is a standard Laravel 12 application. There is no external service to subscribe to and no licence server to phone home: you upload the files, run the installer, and the system is yours.

Installation

1. Upload

Upload the contents of the package to your hosting account. Point your domain's document root at the public folder.

On shared hosting where you cannot move the document root, upload the whole folder and point the domain to /public through your control panel's "document root" setting. Do not move index.php out of public — everything above it is meant to stay unreachable from the web.

2. Create a database

Create an empty MySQL database and a user with full privileges on it. Use utf8mb4_unicode_ci as the collation so Arabic text sorts correctly.

3. Set folder permissions

chmod -R 775 storage bootstrap/cache
chown -R www-data:www-data storage bootstrap/cache

Replace www-data with whatever user your web server runs as.

4. Run the installer

Open https://your-domain.com/install and follow four steps:

  1. Requirements — PHP version, extensions, writable folders
  2. Database — the connection is tested before anything is written to .env
  3. Build tables — migrations plus core data (permissions, roles, languages, settings, ICD-10 codes). Tick Load demo data if you want a populated system to explore
  4. Admin account — your name, email and password
When the installer finishes it writes storage/installed. From that moment /install returns 404, so nobody can re-run it and wipe your data.
The installer also refuses to run migrations against a database that already contains users, even if the lock file is missing. This is deliberate: a re-upload that loses storage/installed must never cost you your records.

5. Remove the demo data (optional)

php artisan demo:clear

This deletes every transactional record — patients, invoices, stock, visits, attendance, leave — while keeping your settings, roles, permissions and ICD-10 catalogue intact. Document numbering restarts from 1, and every financial account is reset to its opening balance, since the transactions behind its balance have just been removed.

Updating to a newer version

  1. Back up your database and the .env file.
  2. Replace all files except .env, storage/ and any logo or uploads you added.
  3. Run php artisan migrate --force.
  4. Run php artisan optimize:clear.
Text you edited in the Translation manager lives in the database, not in the language files. Replacing the files during an update never overwrites your wording.

Branches

Every transactional record carries a branch. Users are assigned to one or more branches and switch between them from the header. A user only ever sees the data of the branch they are currently in — including through direct URLs.

Catalogue data (services, items, suppliers, lab tests) is shared across branches by default, so you define a medicine once and every branch keeps its own stock of it.

Setup → Branches is where you add and edit them. Each branch carries its own tax number, licence number, currency, timezone and opening hours — the tax number is what gets printed on invoices and used to build the e-invoice.

The last active branch cannot be deactivated or deleted. Every screen in the system filters by branch, so with none active a user would sign in to a completely empty system with no explanation. A branch that already holds patients, visits or invoices cannot be deleted either — deactivate it instead so its history survives.

Users

Setup → Users. Each user needs a username, an email, at least one branch, and normally a role.

  • Branches — a user with no branch cannot sign in at all. Give more than one and you can pick which is their default.
  • Roles — applied across every branch the user works in. Someone who is a cashier here and a manager there is rare enough that the screen keeps one role set per person.
  • Employee file — linking one ties attendance, leave and payroll to this account. Without it the user cannot see "my leave requests".
  • Password — leave it blank when editing to keep the current one. Setting a password for someone else automatically flags them to change it at next sign-in, since you now know it.

A branch manager only sees the users of their own branch. Only someone with branches.view-all sees everybody.

You cannot lock yourself out. Nobody can deactivate or delete their own account, and the last active Super Admin cannot be deactivated, deleted, or stripped of the role — any of those would leave the system with no one able to open it, fixable only from the database.

Doctors & clinics

Setup → Doctors & clinics. Two tabs, and the order matters: a doctor's work schedule cannot exist without a clinic, so add clinics first.

Clinics

A clinic is the booking unit — a patient books in a clinic, with a doctor, at a time. Give it a room number, a colour (it identifies the clinic on the calendar and the waiting-room screen) and a default slot length.

Doctors

Beyond the obvious fields, three matter for money and booking:

FieldWhat it does
Consultation feeCharged for a new visit.
Follow-up fee + windowWithin the window, a returning patient is charged the follow-up fee instead.
Commission type & valueThe doctor's default share. Rules under Commissions override it.
Login accountOne account per doctor — this is how the system knows which visits are "mine".

Work schedules

Click the schedule badge on any doctor row to open their weekly schedule underneath. Each line is one day: clinic, from, to, slot length, and an optional appointment cap.

Without a schedule, no appointment slots are calculated for that doctor at all — the booking screen will simply show nothing available. The badge turns amber when a doctor has no schedule so it is visible at a glance.

Two schedules for the same doctor overlapping on the same day are refused: they would let the same free hour be counted twice and two patients be booked into it. Back-to-back shifts (one ending at 13:00, the next starting at 13:00) are fine.

Services & pricing

Setup → Services. A service is anything you invoice for that isn't a medicine, a lab test or a scan. Nothing can be billed until it exists here.

Services live inside categories, so start on the Categories tab — a service cannot be created without one. Both are shared across branches: define a service once and every branch can sell it.

FieldWhy it matters
PriceThe cash price, and the fallback whenever no price list applies.
CostFeeds the profit report. Never shown to the patient.
Floor priceThe lowest price allowed after a discount; below it the invoice needs a manager's approval.
CommissionPercentage or fixed amount for the doctor who performed it.
Requires a doctorUntick for things like a dressing change that any nurse performs.
A floor price above the price itself is refused — it would make every single invoice fall below the floor and need manager approval, stopping the front desk. A percentage commission above 100% is refused for the same kind of reason.

A service that has already been used on a visit or an invoice cannot be deleted, only deactivated, so old reports keep their names.

Price lists

Setup → Price lists. A price list is a different price for the same service depending on who is paying: an insurer, a corporate contract, or staff.

With no price list, every insured patient is charged the cash price — which is always the highest one. If you work with insurers, this screen is not optional.

Create the list, choose its type, and for an insurance list pick the company — an insurance list with no company never reaches a patient, because the invoice finds the list through the patient's company. Then open Prices and add services one by one, or press Fill with all services to copy the whole catalogue at cash price and adjust only what you actually negotiated. Filling never overwrites a price you already agreed.

Each line carries three separate things:

  • Contracted price — what the service costs under this contract.
  • Patient copay % — the share the patient pays at the desk.
  • Covered / not covered — an uncovered service with a price is not a contradiction: the price is what the patient then pays in full.

Services not listed fall back to their cash price. A list used on invoices, or linked to an insurance company, cannot be deleted — deactivate it.

Financial accounts

Finance → Financial accounts. Every payment, refund, expense, payslip, doctor commission, supplier payment and cash drawer lands in one of these: a cash drawer, a bank account, or an e-wallet.

One account is the default — anything recorded without an explicit account goes there, which is why the default cannot be deactivated.

The opening balance is entered once, at creation. After that the balance moves only with real transactions; editing it later would break reconciliation retroactively, so the field disappears on edit.

Transfers

Depositing the day's takings into the bank, or drawing cash out of it, is a transfer. Fees are deducted from the sending account and are not added to the receiving one — the bank keeps them; adding them to both would invent money that never reached anybody.

A cash drawer cannot go negative, and the check includes the fees. A negative cash drawer does not exist in reality, so it is refused rather than recorded.

Settings

Settings holds ten groups — general, invoicing, appointments, queue, pharmacy, laboratory, payroll, WhatsApp, SMS and backup.

Settings are saved per branch and override the global defaults. One branch can allow a 30 % discount without approval while another stays at 10 %.

The settings worth reviewing on day one:

  • general.currency_symbol and general.decimal_places
  • invoice.max_discount_percent — above this a manager must approve
  • invoice.print_size — a4, thermal_80 or thermal_58
  • pharmacy.expiry_alert_days — how early expiry warnings appear
  • payroll.working_days_per_month — the divisor behind every daily rate
  • payroll.late_deduction_method — set to none if you do not deduct for lateness

Translation manager

Settings → Translations lets you rewrite any text in the interface without touching code. Pick a language, pick a file, edit the value, save. The change is live immediately.

Keys come from the language files, so a key added by a future update appears here automatically. Only the values you actually change are stored — text identical to the original is not saved, which keeps improved translations flowing through on updates.

Use the Untranslated only filter when adding a new language to see exactly what is left.

Reception & queue

  1. Patients → New creates the file and assigns an MRN.
  2. Appointments → New books a slot. The system refuses a slot the doctor already has, outside their schedule, or beyond their daily limit — and tells you which.
  3. When the patient arrives, press Check in. A queue token is issued automatically.
  4. Queue shows every clinic's board. Call next announces the token on the waiting-room display.

The doctor's console

Visits is the doctor's home screen: arrived patients as cards on top, today's visits underneath. Start consultation opens the console, which has five tabs:

  • Examination — complaint, history, findings, plan, advice, follow-up date
  • Diagnosis — live ICD-10 search or free text, typed as provisional / primary / secondary / final / ruled out
  • Prescription — drug search showing the pharmacy's live stock beside each item; quantity is estimated from the frequency and duration you type, in Arabic or English
  • Services — procedures priced from the patient's insurance price list
  • Lab & radiology — orders that inherit the patient, doctor and insurance from the visit

Every tab saves as you go — there is no final "save" button to lose work to a dropped connection.

A visit cannot be completed without at least one diagnosis, and once completed the record locks. Corrections are made by adding a new note, never by silently editing history.

Prescription log

Prescriptions are written inside the consultation, alongside the examination and diagnosis. Clinical → Prescriptions is where you find them afterwards — a patient calling a month later to ask what they were given, a pharmacy checking, a doctor looking up what they prescribed last time.

Search by prescription number, patient name, file number or phone; filter by date, doctor, or dispensing status. Open any row to see the drugs with doses, frequency, duration and how much has actually been dispensed.

Print produces the ℞ sheet with the clinic header, the patient's details, the drug table, advice, follow-up date and the doctor's signature and licence number. Send messages the patient a link to that sheet — the link, never the drug names as text, because doses abbreviated into a chat message are dangerous.

A prescription is never edited or deleted here. It is a signed medical document: medicine has been dispensed against it and a paper copy may already have left the clinic. Changing it would make what is in the patient's hand differ from what is in the system.

Billing & cash

Opening a cash session

Before collecting cash, open a session from Cash sessions and enter your opening float. One user has one open session; one register hosts one session. Without an open session, cash collection is refused — so every pound has a named owner and a shift.

Invoicing

From a completed visit press Bill this visit — its services flow into a draft. Add or remove lines, apply a discount, then Issue. Issuing assigns the final number and posts the patient's share to their account statement.

The maths:

subtotal        = Σ (qty × price − line discount)
tax_amount      = Σ line tax
discount_amount = invoice-level discount
total           = subtotal + tax − discount
insurance_share = Σ covered share      ← untouched by your discount
patient_share   = total − insurance_share
balance_due     = patient_share − paid  ← what the patient owes

Closing the session

Count the drawer and enter the figure. The system compares it with what it expected and records the difference as a shortage or surplus. Nothing is silently adjusted. Card and transfer payments never enter the drawer, so they are excluded from the expected cash.

Expenses

Finance → Expenses. Rent, salaries paid in cash, maintenance, utilities — anything leaving the clinic that is not a supplier invoice.

Every expense goes through three stages: recorded → approved → paid. Only the last one actually moves money.

  • Amounts above expense.approval_limit need the approval permission; below it, whoever records can approve.
  • Paying in cash requires an open cash session — the money comes out of a real drawer with a named owner. A bank transfer does not.
  • A paid expense can no longer be edited or deleted. Correct it with a new entry.

Categories can be mapped to specific ledger accounts, so rent and salaries land in the right place in the income statement instead of a single lump.

Pharmacy & stock

Receiving goods

Purchases → New, choose supplier and warehouse, add items with batch number, expiry, cost and any bonus quantity, then Receive goods. Only then does stock move, batches get created and the supplier balance rises.

Dispensing

Dispensing lists prescriptions waiting. Open one and the screen shows what was prescribed, what remains, and live stock for each drug. Adjust quantities, substitute an item if needed, and dispense. Stock is deducted and a pharmacy invoice is issued in the same transaction.

Dispensing follows FEFO — first expired, first out. Expired batches are excluded entirely, so a box that has passed its date can never be handed to a patient even if it is still on the shelf.

Stock-taking

Stock shows quantities, batches and expiry with one-click filters for low stock, near expiry and expired. Press Adjust on any row, enter what you actually counted and pick a reason. The difference is recorded as a movement with that reason attached — never absorbed silently.

Laboratory & radiology

The lab worklist is ordered by urgency, not by date: STAT first, then urgent, then routine.

  1. Collect sample — this is when the turnaround clock starts, not when the doctor wrote the order
  2. Enter results — reference ranges shown beside each parameter are the ones matching this patient's sex and age
  3. Verify — a different person confirms the result
  4. Deliver and print
Nobody can verify a result they entered themselves, an unverified result cannot be delivered, and the printed report contains only verified tests. A page leaving the lab reads as final, so it must be.

Critical values are flagged separately from merely high or low ones, and mark the whole order so the front desk can see at a glance that a doctor needs calling.

Radiology follows the same shape: schedule → perform → report → verify. A final report is never silently replaced; changing it records an amendment with a written reason, because the treating doctor may already have acted on the first version.

Insurance claims

  1. Build claim — pick the insurer and a period; every unclaimed insured invoice is gathered
  2. Submit — the batch locks, because the insurer now holds a copy
  3. Record insurer response — enter the approved amount per invoice; the rejected difference is calculated for you
  4. Record incoming transfer — only the net enters your account, so administrative deductions do not inflate the books
  5. Resubmit rejected — builds a fresh claim from what was cut, and marks the originals so nothing is claimed twice

Resubmission works on partially cut invoices too, which is the common case — insurers usually trim a portion rather than reject the whole thing.

Employees, attendance & leave

Employee files

HR → Employees. Everything in this module hangs off the employee file — attendance, leave, payroll, end-of-service. Link each one to their login account so the two halves connect.

Salary and bank details sit behind a separate permission (employees.view-salary). Whoever records daily attendance needs the employee list but has no business knowing their colleagues' pay, so for them those fields are neither shown nor saved.

The biometric ID is the number stored on your fingerprint device — it is what ties raw punches to a person.

An employee who already has attendance, leave or payslips cannot be deleted. Set their status to terminated or resigned with a date instead — end-of-service is calculated from it, and the history survives.

Attendance

HR → Attendance shows one day at a time for everyone, with arrows to move between days. Four counters at the top answer the only question that matters in the morning: who is in, who is absent, who is on leave, and who has no record at all.

Click any row to enter or correct check-in, check-out, shift and status. Mark the rest stamps everyone without a record — it never touches somebody who actually punched.

MeasuredHow
LatenessAgainst the shift's start time, minus its grace minutes.
Early leaveAgainst the shift's end time, minus its own grace.
OvertimeBeyond the shift's threshold, after the break.
With no shift selected there is no lateness and no overtime — there is nothing to measure against, and inventing a figure would produce a deduction with no basis.

A night shift is handled properly: clocking out at 02:00 after clocking in at 22:00 is four hours worked the next morning, not minus twenty.

Once a month's payroll has been paid or closed, its attendance is locked — changing it would contradict what staff already received.

Leave

HR → Leave. Requests are listed with pending ones first, because the screen is opened to make a decision. The Balances tab shows entitled, used, pending and remaining days per employee per leave type.

A request is checked against the leave type before it is accepted: overlapping requests, remaining balance, gender restrictions (maternity), maximum consecutive days, minimum service, and notice period. Notice is only enforced for future leave — sick leave is filed after the fact, and rejecting it for short notice would be nonsense.

Approving a leave writes it into attendance. Payroll reads the attendance table, not the leave table — so approval creates a leave attendance row for each day. Without that step an employee would be counted absent during their own approved leave and docked for it. Cancelling the leave removes those rows and returns the balance.

A day the employee actually punched is never overwritten by a leave approval: the punch is the truth.

Payroll & commissions

Payroll

Payroll → Open period for a month, then Run payroll. Each payslip is built from six sources: basic salary, effective allowances, approved commissions, overtime, deductions (absence, lateness, loan installments, penalties) and finally social insurance.

Working days come from the attendance records, not from the length of the month — so Fridays and holidays are never counted as absence.

Running the payroll again rebuilds it rather than doubling anything: loan installments are released and re-applied, so a correction costs nothing. Once paid, the period locks for good.

Doctor commissions

Rules cascade from general to specific: a clinic-wide rule, then a rule for one doctor, then a rule for one service. The most specific rule wins.

CalculationMeaning
Percent of netPercentage after the line discount
Percent of grossPercentage before the discount
Fixed per caseA flat amount regardless of price
TieredPercentage that changes with the amount

Administrative expenses are deducted from the base before the doctor's share is worked out, and minimum and maximum caps apply after. A commission entry is created the moment an invoice is issued and can never be created twice for the same line — the database enforces that, not just the code.

Reports

Four sections, each behind its own permission, so the accountant and the HR manager never see each other's numbers.

  • Financial — issued vs collected vs outstanding, revenue by day, collections by method, revenue per doctor net of commission, top services, receivables aging
  • Clinical — visits, completions, new patients, average visit length, visits per doctor, top diagnoses, patient mix
  • Inventory — stock value, low stock, near-expiry and expired batches, slow-moving capital
  • HR — attendance, lateness, overtime, last payroll cost

Consultation templates

A doctor sees the same condition dozens of times a day. A template stores a whole consultation under one name — examination text, diagnosis, prescription with doses, lab and imaging orders — and applies it in one click.

Two rules govern it:

  • Applying adds; it never erases. A text field is only filled if it is empty, and an existing drug or diagnosis is not duplicated. Applying the same template twice changes nothing the second time.
  • Follow-up is stored as a number of days, not a date. A template used months later would otherwise carry a date in the past, which validation rejects.

A template with no doctor is shared with every doctor in the branch; a template with a doctor is personal and invisible to others. Publishing a shared template needs the separate templates.share permission, which the Doctor role does not have — if a doctor ticks the box, the template is saved as personal.

The list orders itself by usage, so the three templates a clinic really uses rise to the top on their own.

Voice dictation

A microphone button sits next to every long clinical field — examination, diagnosis, plan, notes, and the radiology report. Hold a conversation with the patient, dictate the note, keep your hands free.

The audio never leaves the machine. Recognition runs inside the browser (the Web Speech API). There is no server, no API key and no monthly cost. It works in Chrome and Edge; other browsers simply do not show the button.

Arabic medical recognition is imperfect, so the system ships a correction dictionary that rewrites what the engine heard before it reaches the field:

  • Punctuation by voice — saying "نقطة" inserts a full stop, "سطر جديد" a new line.
  • Patterns — "مية وعشرين على تمانين" becomes 120/80, "تلاتين درجة" becomes 30°.
  • Terms — around thirty-five medical terms and drug names that engines habitually mishear.

Setup → Voice dictionary lets the clinic add its own corrections — the drug names and doctors' habits that no shipped list could predict. Rules are applied longest-first, so "فاصلة منقوطة" is never mistaken for "فاصلة".

Only text the engine marks as final is written, so interim guesses never flicker into the record, and the engine restarts itself when it drops out mid-sentence.

Patient queue link

Every queue token carries a random link. Open the queue board, click the scan icon next to a token, and a QR code appears. The patient scans it and follows their turn from their own phone — they can wait in the car and come back on time instead of standing in the hall.

The page shows their number, how many are ahead, an estimate in minutes computed from today's actual average, and which number is being served. When they are called, it turns green and names the room. It refreshes itself every fifteen seconds.

The link is valid for its day only, and it is a random UUID: changing a character in the URL gives a 404, so nobody reaches another patient's ticket. The page shows no other patient's name and no medical data.

WhatsApp messages

Sending is off until you enter your own keys. Until then every message is written to the log so you can see exactly what would have been sent — the system never messages a real number from demo data.

To switch it on: Settings → WhatsApp, tick enabled, then enter the phone_number_id and access_token from your Meta WhatsApp Cloud API app. Local numbers such as 01001234567 are converted to international format before sending.

EventWhen it is sent
Appointment confirmedThe moment a booking is saved
Appointment reminderScheduled task, the evening before
Queue ticket linkOn check-in — the most useful message of the day
Your turnWhen the patient is called
Result readyWhen a verified lab result is delivered
Invoice issuedOff by default

Each event has its own switch in the settings, and the message texts are editable templates — Arabic and English — so you can rewrite them in the clinic's own voice.

A failed message never breaks the operation. If the provider is down, the appointment is still booked and the failure is recorded in Message log with its reason and a retry button.

Who changed what

Settings → Who changed what records every change to sensitive records: patients, visits, invoices, payments, refunds, cash sessions, expenses, items, settings, users, employees, payslips and insurance claims.

Each row names the user, the action, the record, and the change itself as old → new — because the new value alone tells you nothing. Only changed fields are recorded, and a save that changed nothing is not recorded at all, so the log stays readable.

Filter by record type, user, action, and date range.

Backups

Settings → Backups creates one zip holding the database and, optionally, the uploaded files. It does not use mysqldump: many shared hosts block external commands, and a backup that fails on your host is worthless. The export reads the tables through PDO and writes the SQL itself.

Queue, session and cache tables are deliberately excluded — restoring them would revive dead sessions and failed jobs.

A nightly backup runs automatically at 02:30 (database only, since file backups grow without limit), and copies older than the number of days set in the settings are removed.

To restore: create an empty database, import database_*.sql from inside the zip, copy the files folder into storage/app/public, then update .env.

Scheduled tasks

Four things need the scheduler: appointment reminders, marking missed appointments as no-shows, the nightly backup, and sending queued e-invoices. Add one line to your host's cron panel:

* * * * * cd /path/to/app && php artisan schedule:run >> /dev/null 2>&1

Without it the system still works — those run only when you trigger them by hand:

php artisan messages:remind
php artisan appointments:sweep-no-shows
php artisan backup:run
php artisan einvoice:submit
If you use e-invoicing, the scheduler is not optional. Invoices are queued at the moment they are issued and sent every fifteen minutes; with nothing draining the queue they stay pending forever.

Double-entry accounting

Off by default. Turn it on in Settings → Accounting when you are ready. Until then nothing posts — deliberately, so a missing ledger account can never block the front desk from issuing an invoice.

Chart of accounts

Fifty-five accounts ship configured — 1xxx assets, 2xxx liabilities, 3xxx equity, 4xxx revenue, 5xxx expenses. Rename them freely; the system finds them by an internal key, not by name, so renaming never breaks posting. Add your own under any parent.

What posts automatically

Once enabled, fourteen events post on their own: invoice issued, cost of goods, payment received and allocated, refund, expense paid, other income, purchase received, supplier paid, payslip approved and paid, commission accrued, insurance payment received, and cash session closed.

A few of those decisions are worth knowing, because accountants differ on them:

  • A discount is an expense, not reduced revenue — so you can see what discounting actually costs you.
  • A patient advance is a liability until there is an invoice to set it against.
  • An insurance deduction is its own expense line, not a quiet reduction of the claim.
  • Payroll deductions are liabilities (you owe them to someone), not reduced salary expense.
  • Commission accrues when it is earned, at invoice time — not when it is eventually paid.

Turning it on later

If you run the clinic for months and then enable accounting, your history is not lost:

php artisan accounting:repost --from=2026-01-01 --dry-run
php artisan accounting:repost --from=2026-01-01

It is idempotent — running it twice does not double anything. Always run --dry-run first to see what it will post.

Reports and closing

Trial balance, income statement, balance sheet and account statement. The balance sheet includes the current period's result in equity, so it balances before you have closed the year.

A posted entry is never edited. Corrections are made by reversing it, which creates a mirrored entry dated today and links the two. Editing history is how books stop being trustworthy.

Closing a fiscal period is refused while it is out of balance, and closing is a manager's decision, not the bookkeeper's — accounting.periods.manage is a separate permission from writing entries. Each branch closes its own periods independently.

E-invoicing (ZATCA / ETA)

Support for the Saudi authority (ZATCA) and the Egyptian one (ETA). Enable it in Settings → E-invoicing and choose your provider.

Every issued invoice is queued, sent within fifteen minutes, and tracked on Accounting → E-invoices with rejected and pending ones listed first. Rejections carry the authority's reason; fix the cause, then Requeue.

StatusMeaning
PendingQueued, not sent yet.
AcceptedCleared by the authority.
RejectedThe authority refused the data. Not retried automatically — fix and requeue.
FailedA network or server problem on their side. Retried on its own.

The QR code required on Saudi invoices is generated and printed regardless of whether transmission has succeeded, since an invoice may be printed before it clears.

Digital signing needs a certificate issued in your establishment's name, which cannot ship inside a product.
  • ZATCA — a CSID certificate, issued to your establishment after you register with the authority.
  • ETA — signing via a USB token or an HSM.
The fields are waiting in Settings. Until they are filled the document is still built in full and the QR is still produced — the authority simply rejects it with a clear message rather than failing silently.

Issuing an invoice never fails because of e-invoicing. The patient is standing at the desk; the invoice is issued, the reporting is queued.

Built-in safeguards

These are enforced by the system, not by policy documents. They are worth knowing because they explain why the software sometimes says no.

RuleWhy
Reception cannot open the clinical recordComplaint, examination and diagnosis are private to the care team
A visit cannot be completed without a diagnosisA medical record without one has no meaning
No cash collection without an open sessionOtherwise no one owns the shortage at count time
An issued invoice cannot be editedIt is a financial document; it is cancelled with a written reason instead
An invoice with a payment cannot be cancelledRefund first, or debt vanishes while cash stays in the drawer
Whoever requests a refund does not approve itSeparate permissions for requesting and approving
Nobody audits their own cash sessionAn audit by the person being audited is not an audit
Expired medicine is never dispensedExcluded from FEFO entirely; written off through an adjustment
Negative stock is refused by defaultOtherwise stock-taking can never balance and losses stay hidden
Whoever enters a lab result does not verify itVerification is what turns a number into a finding
A final radiology report is amended, never replacedThe treating doctor may have acted on the first version
Controlled drugs need a prescriptionConfigurable, but the default is to refuse
A paid payroll period cannot be re-runThose figures were received by employees

Document numbering

Each document type has its own counter per branch, configurable in prefix, padding, year/month inclusion and reset period. Numbers are drawn inside a locked transaction, so two users pressing save at the same instant can never receive the same number.

DocumentExample
Medical recordMRN-000145
VisitV-2026-000145
InvoiceINV-2026-000145
ReceiptPAY-2026-000145
Lab orderLAB-2026-000145
PayslipPS-2026-09-000145
A draft invoice holds no number at all — it is drawn at the moment of issue. This keeps the tax-visible sequence free of gaps left by drafts that were never issued.

Waiting-room display

Create a display record and open its URL on the waiting-room TV. No login is needed; the random token in the URL is the key, and the branch is fixed by the display itself so it can never show another branch's tokens.

App\Models\QueueDisplay::create([
    'branch_id'       => 1,
    'name'            => 'Main waiting hall',
    'clinic_ids'      => [1, 2, 3],   // empty = every clinic
    'ticker_text'     => ['en' => 'We wish you good health'],
    'refresh_seconds' => 5,
    'is_active'       => true,
]);

Troubleshooting

Blank white page after installing

Almost always a permissions problem. Run chmod -R 775 storage bootstrap/cache and check storage/logs/laravel.log.

"404 Not Found" on every page except the homepage

mod_rewrite is disabled, or Apache is ignoring .htaccess. Enable mod_rewrite and set AllowOverride All on the directory.

The installer says the database is not empty

It found existing users. Either point it at a fresh database or drop the tables — this guard exists so a re-upload can never wipe live records.

Arabic text shows as question marks

The database is not utf8mb4. Convert it:

ALTER DATABASE your_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

Changes to settings are not taking effect

Run php artisan optimize:clear. Settings and translations are cached for speed.

Cash collection is refused

The user has no open cash session. Open one from Cash sessions. This is intentional, not a bug.
